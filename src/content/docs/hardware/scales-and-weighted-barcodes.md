Retailers selling items by weight—such as delis, butchers, bakeries, candy shops, and produce markets—can process weighted goods in Open Source Point of Sale using **Price-Embedded** or **Weight-Embedded Barcodes** generated by deli scales.

---

## 1. How Embedded Barcodes Work in OSPOS

When a customer brings a scale-labeled package to the register, the barcode contains both the **product identity (SKU)** and the **weight or price**.

OSPOS features an advanced, tokenized **Barcode Parser** (`Token_lib.php`) that uses configurable token patterns to extract the item number and calculate the weight or price on the fly.

### The Barcode Tokens

OSPOS recognizes the following token symbols in **Input Formats**:

| Token Pattern | Meaning | Parsing Behavior in Code |
| :--- | :--- | :--- |
| **`{I:length}`** | **Item Number / SKU** | Matches `length` digits and queries the database for matching product `item_number`. |
| **`{W:length}`** | **Weight (in grams)** | Matches `length` digits and divides by `1000` to calculate kilograms in the cart (`$quantity = $parsed['W'] / 1000`). |
| **`{P:length}`** | **Price (in cents)** | Matches `length` digits and converts to decimal price in the cart (`$price = (double)$parsed['P']`). |
| **`{E:length}`** | **EAN / Check Digits** | Matches leading prefixes or trailing EAN checksum digits. |

## 2. Common Barcode Format Patterns

Navigate to **Store Config** $\rightarrow$ **Barcode** $\rightarrow$ **Input Formats** (`barcode_formats`):

```
┌─────────────────────────────────────────────────────────────┐
│ EAN-13 Weight-Embedded (Grams):                             │
│   ^20{I:5}{W:5}{E:1}$                                       │
│                                                             │
│ EAN-13 Price-Embedded (Cents):                              │
│   ^21{I:5}{P:5}{E:1}$                                       │
│                                                             │
│ UPC-A Price-Embedded (Cents):                               │
│   ^02{I:4}{P:5}{E:1}$                                       │
└─────────────────────────────────────────────────────────────┘
```

### Breakdown of a Weight-Embedded Barcode Example:
A deli package scans as `2012345004506`:
- `20`: 2-digit store prefix
- `{I:5}` = `12345`: Matches product with Item Number `12345` (e.g. *Gouda Cheese*)
- `{W:5}` = `00450`: 450 grams $\div$ 1000 = `0.45` kg
- `{E:1}` = `6`: Checksum digit
- **Result in Register Cart**: Gouda Cheese added with **Quantity: 0.45**, calculated at the product's per-kilogram retail price!

## 3. Step-by-Step Setup Guide

### Step 1: Add the Pattern to Store Configuration
1. Go to **Store Config** $\rightarrow$ **Barcode**.
2. Locate the **Input Formats** list.
3. Add your scale's output format pattern (for example, `^20{I:5}{W:5}{E:1}$`).
4. Click **Submit** to save.

### Step 2: Configure the Weighted Product
1. Navigate to **Items** $\rightarrow$ **+ New Item** (or edit an existing weighted item).
2. Set the **Barcode / Item Number** to the item SKU matching `{I:length}` (e.g. `12345`).
3. Set the **Retail Price** as the price per standard unit (e.g. `$12.00` per kg or lb).
4. Save the item.

### Step 3: Test at the Register
1. Open **Sales**.
2. Scan or enter a test barcode (e.g. `2012345005001`).
3. OSPOS parses the string, identifies product `12345`, sets the quantity to `0.5`, and prices the line item at `$6.00`.
